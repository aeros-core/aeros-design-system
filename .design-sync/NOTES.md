# design-sync notes — Aeros React DS

Repo-specific gotchas for syncing `@aeros-core/react` to Claude Design. Read this before a re-sync.

## Shape & scope
- Shape: **package** (no Storybook). The DS exports **77 PascalCase symbols** = ~26 primary components + ~50 compound sub-parts (Card→CardHeader/Body/…, Table→Thead/Td/…, Dialog/DropdownMenu/Select/Tabs/Sidebar/TopNav/Tooltip families). All import fully-functional.
- Preview scope chosen on first sync: **rich authored previews for the ~26 primaries**; pure sub-parts ship the honest floor card (they only render meaningfully inside their parent, which the primary card already shows). Sub-parts are authorable later — drop a `.design-sync/previews/<SubPart>.tsx`.

## Build (this is `cfg.buildCmd`)
- `pnpm build:tokens && pnpm build:react && node .design-sync/compile-css.mjs`
- Tokens MUST build before react (react's `src/styles.css` does `@import "@aeros-core/tokens/css"`).
- `pnpm install` prints "Ignored build scripts: esbuild, sharp" — harmless; `tsup`/esbuild still work (pnpm links the platform binary package).

## CSS is Tailwind v4 and must be compiled (the crux)
- `packages/react/src/styles.css` is shipped as **source** (`@import "tailwindcss"` + `@source "./components/**"` + `@theme` + `@import "@aeros-core/tokens/css"` + a remote Google-Fonts `@import`). The DS expects the host app to run Tailwind; `dist/` contains **no** stylesheet.
- `.design-sync/compile-css.mjs` (committed) compiles it to `packages/react/dist/aeros.css` via `@tailwindcss/postcss` + `postcss`, resolved from the repo's react-docs devDeps (fallback: `.ds-sync`). `cfg.cssEntry` points at `dist/aeros.css`.
- Preview **layout glue uses inline styles**, NOT Tailwind classes — the compiled CSS only scans `src/components`, so utility classes used only in previews wouldn't be generated. Component classes ARE compiled, so components render styled. Colors/fonts in previews use `var(--aeros-*)` token vars.
- The `t-display-*`/`t-h*`/`t-body-*` typography classes seen in `react-docs/app/page.tsx` are **docs-only** (generated by react-docs' own Tailwind, not in the component CSS). Previews avoid them.

## Fonts
- `[FONT_REMOTE]` (expected, non-blocking): the compiled CSS keeps the Google-Fonts `@import` for **Inter** (UI) + **Nunito Sans** (logo); they load at runtime.
- **IBM Plex Mono** (the `--aeros-font-mono` family for data/numerals) is referenced but is NOT in that remote `@import`, so mono text falls back to a system monospace in cards/designs. Acceptable; to fix, add `IBM+Plex+Mono` to the `@import url(...)` in `packages/react/src/styles.css`.

## Render browser
- No chromium was cached. Used the user's installed **Google Chrome** via `DS_CHROMIUM_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"`. Playwright npm is installed in `.ds-sync` WITHOUT a browser (`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm i playwright`). Set `DS_CHROMIUM_PATH` for every `package-validate.mjs` / `package-capture.mjs` run.

## Overlays & layout components (cfg.overrides)
- Overlays render their open state statically: authored with `defaultOpen` (Dialog, DropdownMenu, Select) or `open` (Tooltip), plus `cfg.overrides.<Name> = {cardMode: "single", viewport: "WxH"}`. Radix static-open works fine in headless Chrome.
- `Sidebar` → `{cardMode: "single", viewport: "300x480"}`; `TopNav` → `{cardMode: "column"}` (wide bar).

## Composition source
- `packages/react-docs/app/page.tsx` is the canonical usage gallery for every component — the source of truth for preview compositions (real props + realistic ops/marketplace content: RFQs, buyers, factory lines, ₹ values).

## Known render warns (re-sync should treat these as expected, not new)
- `[FONT_REMOTE]` for Inter / IBM Plex Mono / Nunito Sans / Plus Jakarta Sans.

## Component prop notes (verified against the bundle)
- `Textarea`, `SidebarItem`, `TopNavLink` spread `...props` onto native elements, so `placeholder`/`rows`/`href` work even though they aren't in the emitted `.d.ts` (typed props are a subset).
- `Sidebar` and `TopNav` are **dark surfaces** by design (light text). `Avatar.tone` includes `royal` (blue). `Alert.variant` is only `green|amber|red|blue` (no grey/dark).

## cfg.overrides & [CONFIG_STALE]
- Adding/changing a **graded** override slice (e.g. `viewport`) after a full build makes a scoped `preview-rebuild --components X` abort with `[CONFIG_STALE]` for that component. Fix: run a full `package-build.mjs` (re-stamps `.stories-map.json`), then the scoped rebuild. `cardMode`/`primaryStory` are presentation-only (excluded from the stamp) so they never trigger this; `viewport` does.

## Re-sync risks (what can silently go stale)
- **CSS compile toolchain**: `compile-css.mjs` needs `@tailwindcss/postcss` + `postcss` resolvable. Provided by react-docs devDeps after `pnpm install`; fallback anchor is `.ds-sync/node_modules`. If Tailwind majors past v4, revisit the `@source`/`@theme` handling.
- **Mono font fallback** (above) — a deliberate accepted substitute, not a bug to re-chase.
- Preview layout intentionally uses inline styles; do not "convert to Tailwind classes" expecting them in the compiled CSS.
- The compiled `packages/react/dist/aeros.css` is gitignored (under `dist`); it's regenerated by `buildCmd`, so a re-sync must run `buildCmd` (not just the converter).
