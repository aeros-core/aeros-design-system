# Design System Audit — August 2026

Full audit of the Aeros design system (tokens · React · Flutter · docs · process) against current UI/UX and accessibility standards, plus the remediation shipped in the coordinated **2.0.0** release. Canonical copy: this file. Status column reflects the repo as of the 2.0.0 branch.

**Scope & method.** All four packages read end-to-end by three exploration passes (structure/tokens, React quality, Flutter quality + parity), findings adversarially verified against source, remediation P0+P1 executed in-branch, P2/P3 scheduled below.

**Standards benchmarked:** WCAG 2.2 AA (incl. 2.5.8 Target Size Minimum, 2.4.13 Focus Appearance, 2.3.3 Animation from Interactions, 1.4.3/1.4.11 contrast) · WAI-ARIA 1.2 Authoring Practices · Material 3 (48dp targets) / Apple HIG (44pt) · W3C DTCG token format · Radix / React Aria / shadcn API conventions.

## Executive summary

The system's Radix-backed web half and its token architecture were fundamentally sound; the damage was concentrated in **distribution** (the published bundle crashed Next.js App Router imports), **dark mode** (half the components rendered light-mode colors on dark surfaces), **assistive tech** (form errors invisible to screen readers on web; zero Semantics and sub-24px targets on Flutter), and **honesty of the API** (three byte-identical color ramps propping up variant names like `blue` that rendered grey). None of it was caught automatically because the web had zero tests and CI never ran the Flutter tests it had.

**2.0.0 fixes all eight critical findings and the P1 pipeline/API debt.** Remaining work is component coverage (Toast, Skeleton, Popover, Combobox, DataTable behaviors; Flutter keyboard navigation) and institutionalizing web unit/axe testing.

## Theme deep-dives

**Distribution (A-01).** tsup's rollup-treeshake pass silently dropped every `"use client"` directive (and even a configured banner), so the one published file was server-unsafe. The fix is a post-build prepend plus a CI head-of-file assertion — the class of bug that only ever gets caught by a gate, because local monorepo consumers compile from source and never see it.

**Dark mode & tokens (A-02, A-12, A-13, A-20).** The root cause was architectural: theme-awareness lived only in the 21 alias tokens, while status colors, shadows, and ramp-referencing component classes were static. 2.0.0 makes the token source theme-complete (`semanticDark`, `shadowDark`), routes Tailwind's `@theme` through the vars so utilities flip automatically, and adds three CI gates (contrast, hardcoded-literal grep, Flutter drift) so the pipeline can't silently rot again.

**Web a11y (A-03, A-04, A-06, A-07).** The Radix half was always conformant; the hand-rolled half now is too. The new Field context implements the APG form pattern (label ↔ control ↔ hint/error wiring) without consumers managing ids, and error state cascades to child controls automatically.

**Flutter a11y (A-05, A-17).** The platform gap was stark — the React Button announced busy/disabled states while the Flutter one disappeared from the semantics tree entirely when disabled. Core controls are now announced and 48dp by default. The honest remainder: keyboard traversal (Tabs arrow keys, focus rings beyond Button) and reduced-motion support are P2.

**API honesty (A-14, A-15).** Decision D1 (fully monochrome) resolved the "blue that renders grey" contradiction by renaming to intent (`success/warning/danger/info/neutral/inverse`) everywhere and deleting the duplicate ramps. The workspace brand memory is updated to match — Royal Blue `#2347D9` is retired for good.

## Decision log

| # | Decision | Outcome |
|---|---|---|
| D1 | Blue info variants | **Fully monochrome** — no blue returns; variants renamed to intent; royal/slate ramps deleted; brand memory updated |
| D2 | Breakpoints | **Web scale everywhere** (640/768/1024/1280/1536); size-ladder names shared, per-platform values documented (Flutter taller for touch) |
| D3 | RTL | **Deferred** — India-market, LTR product; new components must use logical properties / `EdgeInsetsDirectional` so the retrofit surface stops growing |
| D4 | Versioning | **Lockstep 2.0.0** across tokens/react/flutter; Flutter gets a CHANGELOG; one breaking window instead of a drizzle |

## Roadmap (remaining)

**P2 — capability (next):**
1. Web essentials: Label, Separator, Spinner, Skeleton, **Toast** (z-token already reserved), AlertDialog, Popover — each with an APG checklist + axe test.
2. Web advanced: Pagination, Combobox/Autocomplete, Drawer/Sheet, Accordion, DataTable behaviors (sorting/selection/loading/empty via `EmptyState`), DatePicker, Stack/layout primitives.
3. Flutter: Tabs rebuild (FocusableActionDetector, arrow-key roving), focus rings across widgets, reduced-motion via `MediaQuery.disableAnimations`, theme-aware MTO danger states, Avatar error fallback, ConfirmDialog scroll, Progress indeterminate, privatize `DottedDashedBorder`, Tooltip + Snackbar widgets.
4. Flutter consumes generated `aeros_tokens.dart` directly (drift gate then becomes a build invariant, not a check).

**P3 — process:**
1. Web test infra: Vitest + Testing Library + jest-axe; ESLint + jsx-a11y; axe sweep of react-docs in CI.
2. Golden tests for Flutter dark mode.
3. Docs regeneration (tokens.md from tokens.json), delete legacy `index.html`, re-run `/design-sync` to refresh the stale ds-bundle (built from 1.2.0), react README.
4. Flutter into the release pipeline (Changesets-driven version check).
